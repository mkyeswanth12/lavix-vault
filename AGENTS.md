## Key conventions observed
- **Config lives in `docker-compose.yaml` (EDIT THIS SECTION: secrets + `x-settings`)** edited directly in the file. Resolution: saved Admin Preferences (session timeout, registration; saved model choices for chat/vision/reranker-toggle) → env var → optional config.yml fallback → code default. No `.env` file anywhere. `docker-compose.yaml` carries every password plus `OLLAMA_URL` as literals gated by the `preflight` service; RSA keys come from the gitignored `./secrets` directory. Startup no longer requires config.yml.
- **Model choices**: `x-settings` holds RERANKER_MODE/MODEL/URL + EMBEDDING_MODEL/DIMENSIONS (5 lines). Embedding/reranker-model are deployment choices (reembed/build to change); chat/vision/reranker-toggle saved in Admin DB always win. Reranker presets are hash-pinned in `reranker/Dockerfile` (bge-base + MiniLM). Dims ≤2000 vector+HNSW, ≤4000 halfvec+HNSW, above refused. Migration 0023 adds `embedding_config` + range CHECK; never edit applied migrations.
- Unit tests never see the real config.yml (`tests/conftest.py` autouse fixture points `LAVIX_CONFIG_FILE` at an absent path).
- psycopg v3 uses `%s`/`%b`/`%t` placeholders only — literal `%` in SQL must be `%%`
- `psycopg v3` Cursor has no `.scalar()` — use `.fetchone()["cnt"]`
- `quick_tags` can be `NULL` — `unnest(NULL)` errors; wrap with `COALESCE(quick_tags, ARRAY[]::TEXT[])`
- `get_db()` is `@contextmanager` — use `with get_db() as conn:`, never `next(get_db())`
- LLM emits `answer_id=12345` as plain text, not JSON; both formats must be stripped
- LLM also emits `Lavix Runtime Answer ID: N`, `Metadata: ...`, `run-scope: ...` as plain text — stripped in both `events.py` and `vault-client.js`
- Params in `HYBRID_SEARCH_SQL` are positional `%s` — inserting/changing a CTE shifts all following param indices
- User is `user_id=2`, not 1
- Local Docker network — API talks to `postgres`, `redis`, `reranker`, `minio`
- 3B extraction model (qwen2.5vl:3b) cannot reliably follow subject/excerpt instructions — post-processing normalizes subject to "I" and uses full message as excerpt
- `agent_runtime/cuga_adapter.py` changes require rebuilding the `lavix-vault-agent` image (separate Dockerfile in `agent_runtime/`)
- `app/graph_memory/worker.py` and `events.py` changes require rebuilding the `lavix-vault` image
